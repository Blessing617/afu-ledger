# performance

## Purpose

定义阿福记账的交互响应预算与测量口径，确保「点开就有反应」，避免功能增加后体感持续劣化。

## Requirements
### Requirement: 交互响应预算
系统 SHALL 在Android 16 真机（Android 16 / HyperOS）上满足下列响应预算，且这些数值 MUST 可被命令行复现测量：

- 冷启动到首帧可见 ≤ 800ms
- 自动记账确认悬浮窗从「识别命中」到「可见」≤ 400ms
- 主界面列表滚动期间，帧耗时超过 32ms 的比例 < 5%
- **设置页上下滑动期间，帧耗时超过 32ms 的比例 < 5%**
- **标签切换转场期间，帧耗时超过 32ms 的比例 < 5%**
- **明细页上下滑动期间，帧耗时超过 32ms 的比例 < 5%**
- **点击「记一笔」到记账面板可用 ≤ 300ms，且全程不被任何底层页面遮挡**
- **记账面板内连续点击数字键盘 40 次，帧耗时超过 32ms 的比例 < 5%**

设置页的滑动预算与首页列表同级：设置页包含更多常驻交互控件（开关、滑块、分类与账户选择），它的卡顿更容易被用户感知。

明细页包含月历与长列表，两部分的滚动都必须满足同一预算。

**测量必须以 release 构建进行。** debuggable 构建的 ART 运行校验会让帧耗时显著虚高
（实测同一场景 debug p99 65ms vs release p99 12ms），用 debug 数据下结论会得出错误方向。

#### Scenario: 悬浮窗在预算内可见
- GIVEN 无障碍服务已连接且完成预热，自动记账总开关开启
- WHEN 识别流程产出一笔有效支付草稿
- THEN 从命中日志时间戳到悬浮窗可见的时间差 ≤ 400ms
- AND 该时间差被写入识别日志供查询

#### Scenario: 冷启动预算
- GIVEN 应用已安装在Android 16 真机 上，进程未运行
- WHEN 执行 `adb shell am start -W -n com.afu.ledger/.MainActivity`
- THEN `TotalTime` ≤ 800ms

#### Scenario: 滚动不产生可见掉帧
- GIVEN 首页存在至少 50 条交易记录
- WHEN 用户连续快速滚动列表 10 秒
- THEN `dumpsys gfxinfo` 中超过 32ms 的帧占比 < 5%

#### Scenario: 设置页上下滑动不卡顿
- GIVEN 用户停留在设置页，自动记账区块可见（含账户与分类选择）
- WHEN 用户连续上下滑动手势 10 秒
- THEN `dumpsys gfxinfo com.afu.ledger` 中超过 32ms 的帧占比 < 5%
- AND 滑块拖动时视觉跟随不滞后

#### Scenario: 明细页滚动不卡顿
- GIVEN 用户停留在明细页，月历与分组列表均可见
- WHEN 用户连续滑动手势 10 秒
- THEN `dumpsys gfxinfo com.afu.ledger` 中超过 32ms 的帧占比 < 5%
- AND 月历月份切换时列表不白屏

#### Scenario: 记账面板不被遮挡且在预算内
- GIVEN 用户在任意底部标签页
- WHEN 用户点击中央记账按钮
- THEN 面板完整绘制在最上层，遮罩下的页面不可交互
- AND 面板在 300ms 内可用

#### Scenario: release 构建下测量
- GIVEN 需要验证上述任一预算
- WHEN 采集 `dumpsys gfxinfo` 或识别日志
- THEN 使用的 APK 为 release 构建（非 debuggable）
- AND 报告里注明构建类型与设备型号

### Requirement: 悬浮窗预热复用
系统 SHALL 在无障碍服务连接后预先完成悬浮窗所需的 Compose 初始化，使「首次弹出」与「后续弹出」的耗时处于同一量级；MUST NOT 在每次弹出时重新创建组合环境。

#### Scenario: 首次弹出不再有冷启动惩罚
- GIVEN 无障碍服务刚连接完成，尚未弹出过任何悬浮窗
- WHEN 首次识别命中
- THEN 悬浮窗可见耗时与第二次弹出相差不超过 100ms

#### Scenario: 预热失败不影响功能
- GIVEN 预热过程中发生异常（如窗口权限被撤销）
- WHEN 用户完成一笔支付并命中
- THEN 仍然尝试正常弹出悬浮窗
- AND 失败时写入识别日志，不静默吞掉

### Requirement: 背景图加载不突现
系统 SHALL 让自定义背景图在**首帧就可见**，并且避免任何黑屏 / 白屏跳变。

实现 MUST 同时满足：

- 图片就绪前 MUST 用**占位缩略图**（≤ 96px 宽）铺满，解码耗时 MUST 在一帧以内；缩略图缺失时才回退到主题底色
- 背景图 MUST 按**屏幕像素尺寸**解码（1:1），MUST NOT 按原始分辨率解码 —— 显示区域只有屏幕大小且用 Crop 铺满，原分辨率解码只会拖慢首帧、抬高合成带宽
- 预加载与界面显示 MUST 共用同一 `memoryCacheKey`，冷启动预热才对界面生效
- 原图就绪后以淡入（≤ 200ms）覆盖占位图，MUST NOT 硬切
- 缩略图 MUST 在「设置背景图」时生成，并在启动时自动补齐缺失的缩略图

#### Scenario: 冷启动首帧就有背景
- GIVEN 用户已设置自定义背景图，且已有占位缩略图
- WHEN 冷启动应用并抓取首帧
- THEN 首帧已经能看到背景图（可以是模糊占位）
- AND 不出现纯色底空窗
- AND 原图在 1.5 秒内淡入覆盖占位图

#### Scenario: 大图不按原始分辨率解码
- GIVEN 用户选择一张 4000×3000 的照片作为背景
- WHEN 冷启动应用
- THEN 解码后的位图尺寸为屏幕像素尺寸（1440×3200 级别）
- AND 冷启动 `TotalTime` ≤ 800ms

#### Scenario: 缩略图缺失时自动补齐
- GIVEN 用户在本版本之前就已设置过背景图（没有缩略图文件）
- WHEN 升级后第一次启动应用
- THEN 启动时自动生成缩略图
- AND 第二次冷启动时首帧即可见背景

## ADDED Requirements

### Requirement: 首帧主题正确
系统 SHALL 在冷启动的首帧就使用用户已保存的主题色、深色模式与背景图设置，MUST NOT 先渲染默认主题再切换。

#### Scenario: 冷启动不闪默认主题
- GIVEN 用户已把主题色设为「樱花粉」并开启深色模式
- WHEN 冷启动应用
- THEN 首帧即为樱花粉 + 深色
- AND 不出现默认紫色主题的中间帧

#### Scenario: 背景图首帧即就位
- GIVEN 用户已设置自定义背景图
- WHEN 冷启动应用
- THEN 首页首帧就带背景图，而不是先显示纯色再淡入

### Requirement: 常驻标签页的后台开销上限
系统 SHALL 让不可见的底部标签页不产生周期性重组或无效绘制，MUST NOT 因为「页面常驻」而让不可见页面持续刷新。

不可见标签页 MAY 保留组合树以换取切换速度，但 MUST 满足：

- 没有定时器在不可见时继续驱动状态变更
- 没有无限动画在不可见时持续运行
- 完全透明的页面 MUST NOT 继续产生绘制指令

定时刷新类状态 MUST 在列表容器（如 `LazyColumn`）**之外**订阅一次后传入，
MUST NOT 在列表 item 内部持有定时器或订阅共享 Flow —— 那会让每次 tick 同时失效所有可见 item。

#### Scenario: 不可见页面不触发重组
- GIVEN 用户停留在首页标签页
- WHEN 观察 30 秒内的重组与绘制次数
- THEN 设置页与资产页不产生因定时刷新导致的周期性重组
- AND 应用不因此持续重绘

#### Scenario: 回到标签页时立即显示最新状态
- GIVEN 用户在资产页新建了一个账户
- WHEN 用户切回首页
- THEN 首页显示的账户相关数据是最新的
- AND 不出现明显的「先显示旧值再跳变」

### Requirement: 记账面板的响应与帧预算
系统 SHALL 让记账面板的打开与输入保持「点下去就有反应」，并且不因键盘与分类格增加而掉帧。

预算：

- 点击「记一笔」到面板可交互 ≤ 300ms
- 数字键盘单次点击到金额数字更新 ≤ 1 帧（不排队、不延迟）
- 连续点击键盘 40 次期间，超过 32ms 的帧占比 < 5%
- 打开面板时 MUST NOT 触发首页列表的重新组合

#### Scenario: 面板打开在预算内
- GIVEN 用户在首页，应用已运行
- WHEN 点击中央记账按钮
- THEN 面板在 300ms 内可交互
- AND 首页列表不重新组合

#### Scenario: 连续输入不掉帧
- GIVEN 记账面板已打开
- WHEN 连续快速点击数字键 40 次
- THEN `dumpsys gfxinfo` 中超过 32ms 的帧占比 < 5%
- AND 金额数字与点击同步更新

### Requirement: 主题切换的性能边界
系统 SHALL 在切换主题风格或主题色时，以「一次重组」完成换色换形。

主题切换 MUST：

- 在 200ms 内完成（视觉上完成切换）
- MUST NOT 使用会持续重组整棵树的逐帧颜色动画
- MUST NOT 造成白屏、闪烁或重建页面
- 切换后 MUST NOT 留下持续运行的动画

#### Scenario: 切换主题不卡顿
- GIVEN 用户在外观与主题页
- WHEN 连续切换 4 个主题风格
- THEN 每次切换在 200ms 内完成
- AND 不出现白屏
- AND 超过 32ms 的帧占比 < 5%

#### Scenario: 切换后无残留动画
- GIVEN 用户刚完成一次主题切换
- WHEN 静置 10 秒
- THEN 没有任何动画在持续运行

### Requirement: 装饰层与插画的开销上限
系统 SHALL 让主题装饰与吉祥物插画不成为常驻开销。

要求：

- 装饰由矢量一次性绘制，MUST NOT 每帧重新构建路径对象
- 装饰 MUST NOT 使用无限循环动画
- 页面不可见时 MUST NOT 产生绘制指令
- 装饰图层 MUST NOT 因为滚动而重新组合

#### Scenario: 滚动时装饰不重组
- GIVEN 用户在大肥鱼主题下快速滚动明细页
- WHEN 观察重组与绘制
- THEN 背景装饰不参与重组
- AND 列表滚动帧耗时超 32ms 的占比 < 5%

#### Scenario: 不可见页面不绘制装饰
- GIVEN 用户停留在资产页
- WHEN 观察绘制调用
- THEN 首页与明细页的装饰层不产生绘制指令

### Requirement: 自定义背景下的滚动不降级
系统 SHALL 在「设置了自定义背景图」的前提下，让首页、明细页、设置页的快速滑动仍满足既有帧预算：超过 32ms 的帧占比 < 5%。

- 背景层 MUST NOT 因为列表滚动而重新组合或重新解码
- 背景图纹理尺寸 MUST 不超过屏幕像素尺寸

#### Scenario: 大背景图 + 长列表滚动
- GIVEN 已设置一张照片背景，明细页有 300 笔跨 20 天的交易
- WHEN 在 release 构建上连续快速滑动 10 次
- THEN `dumpsys gfxinfo` 中 Janky 帧占比 < 5%
- AND 90 分位帧耗时 ≤ 16ms

#### Scenario: 背景层不随滚动重建
- GIVEN 背景图已显示
- WHEN 用户滚动明细页
- THEN 背景层的绘制指令不重新生成（仅参与合成）
