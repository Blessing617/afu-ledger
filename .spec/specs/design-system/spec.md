# design-system

## Purpose

定义阿福记账的视觉语言：清爽、圆润、可个性化，所有页面共用同一套主题与形状约束。

## Requirements

### Requirement: 圆润控件风格
系统 SHALL 在全局使用大圆角与胶囊形控件，形成统一的柔和视觉。

#### Scenario: 主操作按钮为胶囊形
- GIVEN 任意屏幕上的主操作按钮
- WHEN 按钮被渲染
- THEN 其形状为胶囊形（圆角半径等于高度的一半）
- AND 点击水波纹被裁剪在胶囊形状内

#### Scenario: 卡片与输入框圆角统一
- GIVEN 首页卡片与记账页输入框
- WHEN 两者被渲染
- THEN 卡片圆角为 20dp、输入框圆角为 16dp
- AND 两者圆角来自同一份 Shape 定义，修改后全应用同步生效

### Requirement: 主题色切换
系统 SHALL 提供一组预设主题色，用户选择后全应用立即生效并持久保存。

色板 MUST 以**居中的等宽网格**排列，MUST NOT 出现「一行没填满就靠左堆」的参差版式；每个色点的点击热区 MUST 覆盖色点与其标签。

#### Scenario: 切换主题色
- GIVEN 用户停留在设置页
- WHEN 用户从色板中选择「樱花粉」
- THEN 主色、强调色与导航选中态立即变为粉色系
- AND 重启应用后仍保持樱花粉

#### Scenario: 色板居中且对齐
- GIVEN 设置页的主题色板包含 8 个预设
- WHEN 它在任意屏宽下渲染
- THEN 色点按固定列数居中对齐
- AND 不存在最后一行只剩一两个色点却贴在左侧的情况

### Requirement: 背景图换肤
系统 SHALL 允许用户从相册选择一张图片作为主界面背景，并自行调节其「存在感」，同时保证文字可读。

可调项 MUST 至少包含：背景可见度、模糊开关、暗色遮罩开关。可见度 MUST 为连续值而不是固定档位。

**背景图 MUST 以原始分辨率显示，MUST NOT 为了性能而降低解码分辨率。**

遮罩只作用于背景层，MUST NOT 降低卡片与文字本身的不透明度。

#### Scenario: 调高背景可见度
- GIVEN 用户已设置自定义背景图，可见度处于默认值
- WHEN 用户把可见度调到最高
- THEN 背景图片清晰、接近原图色彩
- AND 卡片与正文仍保持当前配色可读，不随背景变淡

#### Scenario: 背景保持原始分辨率
- GIVEN 用户选择了一张高于屏幕分辨率的图片
- WHEN 应用渲染背景
- THEN 背景按原图分辨率解码并显示
- AND 放大查看时不出现因降采样导致的模糊

#### Scenario: 背景与文字对比度不足时自动托底
- GIVEN 用户把可见度调高且关闭暗色遮罩
- WHEN 背景某区域为浅色、正文为深色
- THEN 卡片容器仍保持不透明底色
- AND 正文不在背景图上直接绘制

#### Scenario: 开启模糊
- GIVEN 用户已设置背景图
- WHEN 用户开启「模糊」开关
- THEN 背景图以模糊形式渲染
- AND 调节可见度时模糊程度不跳变

#### Scenario: 恢复默认背景
- GIVEN 用户已设置自定义背景
- WHEN 用户点击「恢复默认」
- THEN 主界面背景回到主题色渐变
- AND 可见度、模糊、遮罩参数一并重置为默认值

#### Scenario: 背景显示参数持久化
- GIVEN 用户调整了可见度与模糊开关
- WHEN 重启应用
- THEN 背景与参数均保持

### Requirement: 深色模式
系统 SHALL 支持跟随系统、强制浅色、强制深色三种模式，并持久保存用户选择。

#### Scenario: 跟随系统
- GIVEN 用户选择「跟随系统」，且系统处于深色模式
- WHEN 应用启动
- THEN 应用以深色配色渲染
- AND 背景图换肤在深色模式下同样保持可读

### Requirement: 页面转场与动效
系统 SHALL 为页面切换、浮层出现与列表变化提供**符合层级关系**的过渡动效，使操作自然连贯而不是硬切或生硬平移。

动效 MUST 满足：

- **同级切换**（底部标签之间）：位移幅度 MUST 不超过屏宽 12%，MUST NOT 整屏平移；并 MUST 遵守下面「动效的连贯性」中对方向与纵深的要求
- **层级进入**（标签页 → 二级页面，如分类管理）：从下方滑入，并配合淡入；返回时向下退出
- **层级返回**（二级页面 → 标签页）：方向必须与进入时相反
- **层级遮挡正确**：二级页面在转场的**每一帧**都必须绘制在标签页内容之上，MUST NOT 被标签页内容、悬浮操作按钮或底部导航盖住
- **对话框浮层**：新增类操作使用居中对话框 + 遮罩，由对话框自身提供动效，不参与页面转场的位移
- 缓动 MUST 使用减速曲线或 spring，MUST NOT 线性匀速
- 时长分档统一：同级切换 ≤ 200ms，层级进入 ≤ 260ms
- 系统开启「移除动画」时退化为无动画

底部的悬浮操作按钮与二级页面不属于同一层级：进入二级页面时，标签页侧的一切可见元素（含悬浮按钮、底部导航）MUST NOT 出现于二级页面之上。

#### Scenario: 标签之间切换
- GIVEN 用户在首页
- WHEN 点击「资产」标签
- THEN 新页面以淡入 + 带方向的水平位移出现
- AND 旧页面向相反方向同时淡出
- AND 不出现两页整屏平移的「推卡片」感
- AND 时长不超过 200ms

#### Scenario: 进入二级页面
- GIVEN 用户在设置页
- WHEN 点击「管理分类」
- THEN 分类管理页从屏幕下方滑入
- AND 时长不超过 260ms

#### Scenario: 进入二级页面时不被标签页遮挡
- GIVEN 用户在设置页
- WHEN 进入分类管理页
- THEN 从转场第一帧开始，目标页就完整绘制在最上层
- AND 标签页侧悬浮按钮与底部导航不在其上可见

#### Scenario: 从二级页面返回
- GIVEN 用户在分类管理页
- WHEN 点击返回
- THEN 页面向下滑出
- AND 回到发起它的那个标签页，方向与进入时相反

#### Scenario: 缓动不做匀速
- GIVEN 任意一次转场
- WHEN 观察位移曲线
- THEN 起始快、结束慢（减速），不出现线性匀速移动

#### Scenario: 关闭系统动画
- GIVEN 系统动画缩放为 0 或启用减弱动效
- WHEN 发生任意转场
- THEN 直接切换，不播放动画
- AND 功能行为不变

### Requirement: 动效的连贯性
系统 SHALL 让界面过渡呈现**连续的空间关系**，而不是「一页消失、另一页凭空出现」。

判断标准不是帧率，而是三件事：

- **有方向**：同级切换（底部标签）时，新页面从它在导航栏中的相对方位进入（切到右边的标签，内容从右方来），旧页面向相反方向离开。MUST NOT 所有切换都使用同一个方向或纯淡入淡出。
- **有纵深**：离开的页面略微缩小并后退、进入的页面从略小恢复到原尺寸，使两个全屏层交叠时仍有前后关系。缩放幅度 MUST 足够可见（不小于 3%）又 MUST NOT 夸张到像缩放动画。**缩放 MUST 采用「放大收敛」方向（起点 ≥ 1.0）**，避免页面内缩时四周露出底色。
- **有落位感**：形变与位置动画 MUST 使用 spring 或减速曲线，MUST NOT 线性匀速。

系统 SHALL 为动效提供统一的曲线与时长 token，各页面 MUST 复用同一套 token，MUST NOT 各自写死时长与曲线——不一致的曲线拼在一起会表现为「一段快一段慢」。

动效 MUST NOT 以牺牲流畅度为代价：转场期间 MUST NOT 出现掉帧（超过 32ms 的帧占比 < 5%）。

#### Scenario: 标签切换有方向
- GIVEN 用户在「记账」（最左）标签
- WHEN 点击「设置」（最右）标签
- THEN 设置页从右侧进入
- AND 记账页向左离开
- AND 反向操作时方向也相反

#### Scenario: 标签切换有纵深且不露边
- GIVEN 用户从一个标签切到另一个
- WHEN 观察转场中间帧
- THEN 进入的页面由略大尺寸收敛到原尺寸
- AND 页面上方与下方都不露出 Scaffold 底色
- AND 两页交叠时不出现「两块全屏硬叠」的扁平感

#### Scenario: 动效不用线性匀速
- GIVEN 任意一次页面或弹层转场
- WHEN 观察位移或缩放曲线
- THEN 曲线为 spring 或有加速/减速段
- AND 不出现整段匀速移动

#### Scenario: 曲线与时长来自统一 token
- GIVEN 代码中任意一处转场
- WHEN 检查其 `animationSpec`
- THEN 引用的是统一动效 token
- AND 不直接写魔数时长或默认 linear easing

#### Scenario: 转场不掉帧
- GIVEN release 构建
- WHEN 连续快速切换标签 40 次
- THEN 超过 32ms 的帧占比 < 5%
- AND 转场本身不引入可感知的卡顿

### Requirement: 新增类操作的交互语言统一
系统 SHALL 用**同一种层级表现**呈现所有「新增 / 编辑一个条目」的操作（新增账户、编辑账户、记一笔、编辑记录），使两条完全不同的业务流程不需要用户学两套交互。

该统一形式 MUST 为**居中对话框 + 遮罩**：内容在居中小卡片内，背景变暗，出入口动效由对话框自身提供（缩放 + 淡入）。

对话框内容超出可用高度时 MUST 在正文区内滚动，MUST NOT 让整个对话框溢出屏幕或被裁切。

#### Scenario: 新增账户与记一笔表现一致
- GIVEN 用户在资产页
- WHEN 点击「新增账户」
- THEN 以居中对话框 + 遮罩形式展示
- AND 控件风格（圆角输入框、胶囊选项、取消/确认按钮位置）统一

#### Scenario: 记一笔与新增账户表现一致
- GIVEN 用户在首页
- WHEN 点击「记一笔」
- THEN 以居中对话框 + 遮罩形式展示
- AND 不使用整页滑入

#### Scenario: 内容过多时在对话框内滚动
- GIVEN 设备的可用高度较小，或分类数量较多
- WHEN 记一笔对话框内容超出高度
- THEN 只有正文区滚动，标题与底部按钮始终可见
- AND 对话框本身不被裁切或超出屏幕

#### Scenario: 返回键只关闭对话框
- GIVEN 记一笔对话框已打开
- WHEN 用户按系统返回键
- THEN 只关闭该对话框
- AND 停留在原来的标签页，不退出应用

### Requirement: 应用图标

系统 SHALL 使用「大肥鱼」形象作为自适应图标（adaptive icon），在 HyperOS 桌面、最近任务与设置的应用列表中都正确显示，且前景主体不超出安全区。

图标 MUST 以矢量或高分辨率位图提供，适配圆形、圆角方形、方形三种遮罩。

#### Scenario: 桌面显示自适应图标
- GIVEN 应用已安装
- WHEN 用户在桌面查看图标
- THEN 显示大肥鱼形象而不是系统默认图标

#### Scenario: 不同遮罩下不被裁切
- GIVEN 系统使用圆形遮罩
- WHEN 渲染图标
- THEN 大肥鱼主体完整可见，耳朵/尾巴不被裁切

#### Scenario: 图片未就绪时的降级
- GIVEN 图标前景资源缺失或解析失败
- WHEN 构建 APK
- THEN 构建失败并给出明确错误，而不是产出无图标包

### Requirement: 分类图标与色彩
系统 SHALL 为每个分类提供图标与底色，使首页列表、分类管理与报表排行里的同一分类视觉一致。

图标集 MUST 至少覆盖餐饮、交通、购物、居住、娱乐、医疗、教育、人情、其他、工资、奖金、理财等常见分类。

分类管理页 MUST 允许用户在编辑分类时从图标集中挑选图标，并即时预览。

#### Scenario: 首页显示分类图标
- GIVEN 存在分类「餐饮」与「其他」
- WHEN 首页渲染这两类交易
- THEN 两者都显示各自的图标与底色
- AND 不再出现统一的灰色省略号图标

#### Scenario: 新增分类时挑选图标
- GIVEN 用户在分类管理页新增分类
- WHEN 用户点开图标选择并选中一个图标
- THEN 预览区立即显示该图标与名称
- AND 保存后该分类在所有列表里使用同一图标

#### Scenario: 报表与列表图标一致
- GIVEN 某分类在首页显示为「餐饮」的药丸图标
- WHEN 用户打开报表页查看分类排行
- THEN 该分类在排行里使用同一图标与底色

### Requirement: 图片选择与预览
系统 SHALL 让「从相册选择背景」成为一个可预览、可撤销的操作，而不是选完才知道效果。

选择区 MUST 提供：当前背景的缩略预览、鲜明的「选择图片」入口、以及有背景时的「恢复默认」入口。

#### Scenario: 已设置背景时的选择区
- GIVEN 用户已设置自定义背景图
- WHEN 用户进入设置页的背景区块
- THEN 显示当前背景的缩略预览
- AND 同时提供「更换图片」与「恢复默认」

#### Scenario: 未设置背景时的选择区
- GIVEN 用户尚未设置背景图
- WHEN 用户进入设置页的背景区块
- THEN 显示主题色渐变的占位预览
- AND 只显示「选择图片」入口

### Requirement: 动效与流畅度
系统 SHALL 让所有新增界面复用现有动效 token，并在低端负载下保持流畅。

新增页面进入、图表出现、列表项增删 MUST 使用 spring 或减速曲线；MUST NOT 出现整段匀速位移。

报表与日历 MUST NOT 在滚动或展开时引入持续运行的无限动画。

#### Scenario: 报表进入有落位感
- GIVEN 用户从首页进入报表页
- WHEN 转场播放
- THEN 页面自上而下带缩放收敛地进入
- AND 时长不超过 260ms

#### Scenario: 图表不持续动画
- GIVEN 报表页已展示完毕
- WHEN 静置 10 秒
- THEN 图表不产生周期性重绘
- AND 应用不持续占用 CPU
