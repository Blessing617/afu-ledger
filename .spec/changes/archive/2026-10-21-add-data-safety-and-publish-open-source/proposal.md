# 变更：数据记忆化保障 + 开源发布 v1.0.0

## 动机

两件事绑在一起做，因为它们都指向同一个目标：**这套记账要能长期用下去，并且能作为公开作品拿得出手。**

1. **不知道升级后数据还在不在。** 目前的 release 包用的是 debug 签名，而 Room 虽然配了 AutoMigration，但没有任何验证迁移是否真的能用的测试；也没有「把数据导出去、换手机导回来」的出口。用户准备从清空数据开始认真使用，意味着之后每一笔账都变得有成本 —— 一旦某次升级把数据搞丢，损失是不可接受的。
2. **要开源到 GitHub。** 仓库里还留着 84 张从真机采集的真实账单截图（真实商户、金额、交易单号）、README 里写着设备型号、git 提交历史里带着 QQ 邮箱；许可证是 MIT（允许商用，与「不许别人拿去商用」相反）；也没有 release 包和页面截图。这些在公开仓库里都是必须处理掉的。

## 范围

在范围内：

- **升级不丢数据**：固定签名（同一 keystore 覆盖安装）、迁移测试、schema 入库
- **本地备份**：把全部账本导出成一个 JSON 文件（用户选位置），可再导入还原
- **数据管理**：设置页显示数据量，提供「清空全部数据」（二次确认）
- **清空设备现有数据**（一次性操作，为正式使用让路）
- **release 构建**：versionCode/versionName 更新、release APK 产出与签名核对
- **仓库开源化**：非商用许可证、隐私清理（含 git 历史重写）、README 图文重写、第三方许可说明
- **GitHub 发布**：创建公开仓库、推送、打 tag、Release 附 APK
- **截图**：release 版、用假数据重新截取

不在范围内：

- 云同步、账号体系、多设备同步
- 真实账单样本集（`test/bill-samples`）的上游保留方案 —— 它含真实隐私数据，**从公开仓库移除**，本地留档另说
- 用正式上架商店的签名与隐私政策（这是自用 App，不上架）
- 自动备份（后台定时导出）—— 手动导出已足够，且更省电、更可控
- OCR / 自动记账功能的任何行为变更

## 方法

签名换成一把握在本地（不入库）的项目专用 keystore，release 包与用户手机上的包签名一致，系统更新即为覆盖安装；同时补 Room 迁移测试，让「升级打不开」在 CI/本机就被拦住。备份用 JSON、流式读写（SQLite 逐表分页读出，不整表进内存），通过 SAF 让用户选保存位置，文件只有几十 KB 量级。仓库侧：重写 git 历史去掉真实账单截图与 QQ 邮箱（提交者改成 GitHub noreply 地址），改用 PolyForm Noncommercial 1.0.0，README 用 release 版截图重排。
