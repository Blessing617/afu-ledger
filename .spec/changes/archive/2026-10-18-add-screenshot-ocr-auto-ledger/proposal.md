# 变更：截图 OCR 自动记账（补上微信）

## 动机

v0.2.0 的无障碍通道对**支付宝有效、对微信完全无效**。上一个变更的真机结论很明确：微信（聊天、账单列表、账单详情、支付成功页）是自绘渲染，`rootInActiveWindow` 文本为 0，加 `flagIncludeNotImportantViews` 与全窗口遍历依旧为 0 节点。

同时验证到一条可行路线：service 声明 `android:canTakeScreenshot="true"` 后，`AccessibilityService.takeScreenshot()` 在Android 16 真机（Android 16 / HyperOS）上成功返回 1440×3200 画面，微信账单页文字清晰可辨。也就是说，**截图 + 离线 OCR 是微信唯一可行的自动记账路线**。

本次变更把微信补上：微信在前台且页面稳定后截图 → 纯离线 OCR 出文本 → 交给**现有的**页面规则、金额解析、商户提取、去重、悬浮窗入账链路，不重写这些组件。

硬约束（来自需求）：

- **纯离线**：不申请 `INTERNET`，OCR 模型打包进 APK，识别全在本机
- **Android 16 真机 上耗电可控**：不能每个无障碍事件都截图，必须节流
- **宁可漏记不可记错**：OCR 会误识别（`-42.00` → `-42.OO`），拿不准直接放弃
- **验收不花钱**：用微信历史账单详情页 + debug 模拟页验证，不做真实支付

## 范围

在范围内：

- 新增截图文本采集通道：`takeScreenshot()` → Bitmap → 离线 OCR → 文本行列表
- 把 OCR 文本包装成现有 `PageSnapshot`，复用 `PaymentPageDetector` / `AmountParser` / `MerchantExtractor` / `DetectionDeduper` / 悬浮窗 / 入账
- 触发节流：只在微信（debug 构建额外含本应用）前台、页面事件静默后截图，设最小间隔与连续失败退避
- OCR 结果纠错与放弃规则（全角半角、数字上下文里的 `O→0` / `l→1` 等、严格金额格式、单金额、支付特征词）
- OCR 模型打包与首次解压（assets → `filesDir`），ABI 裁剪以控制 APK 体积
- 设置页新增「截图 OCR」开关与运行状态（OCR 真机可用性、最近一次 OCR 耗时）
- 识别日志补充 OCR 专用的失败原因（截图失败、OCR 无文本、纠错后仍不合规等）

不在范围内：

- **真实支付验证**：不做真实扣款，验收走历史账单详情页与 debug 模拟页
- **收入自动记账**：微信收款、红包、转账到账一律不处理，仍只做支出
- 支付宝改用 OCR：支付宝节点可读，继续走无障碍通道，**不截图**（省电）
- 通知监听通道、短信通道
- 微信之外的自绘页面（淘宝、美团、抖音等自有收银台）
- 云端 OCR、在线模型下载、模型热更新（违反「纯离线」约束）
- 多屏 / 分屏 / 悬浮窗场景下的截图（只处理默认显示器）
- 截图内容落盘、截图导出、识别历史留存
- 自动分类（关键词库）
- Tesseract 之外的第二套 OCR 引擎并行（选型对比只落在 design，代码里只实现一套）

## 方法

把「文本来源」抽象出来：现有识别链路吃的是 `PageSnapshot(packageName, texts)`，而 `texts` 来自无障碍节点。这次再提供一个**截图 OCR 的文本来源**，产出同样形状的 `PageSnapshot`，后面所有判定、解析、去重、弹窗、入账**一行都不用改**。

具体：

- OCR 只在无障碍文本几乎为空的受支持页面上兜底（微信），支付宝不触发
- 截图前做节流判定（前台包名、屏幕点亮、最小间隔、连续失败退避），判定逻辑做成纯 Kotlin 状态机，可单测
- OCR 模型（PP-OCR 移动版 det + rec）打在 assets 里，首次启动解压到私有目录；引擎封装成接口，便于替换与单测替身
- OCR 出来的文本先过一层纠错与清洗（纯 Kotlin，可单测），再进 `PageSnapshot`
- 截图只在内存里存在，识别完立即释放，不写文件、不进数据库、不进日志

验收方式（不花钱）：微信**历史账单详情页**（`我 → 服务 → 钱包 → 账单`，点开一笔旧交易）验证真实页面 OCR 可用性；debug 内置模拟页扩出「微信支付成功全屏页」「OCR 噪声页（`-42.OO`）」「反白字页」等场景验证纠错与放弃规则；支付宝与手动记账做回归。

## 风险

- **OCR 误识别导致记错账**：用「严格校验 + 单金额 + 拿不准就放弃」兜底，并且仍要用户点「记一笔」才入账，最坏情况是多一次打扰而不是错账
- **耗电与卡顿**：截图 + OCR 是重操作（数百毫秒）。用节流 + 单飞 + 超时 + 退避控制；只在微信前台触发，支付宝不触发
- **APK 体积增长**（OCR 引擎 + 模型约 20–35 MB 量级）：用 ABI 裁剪只保留 `arm64-v8a`，并在任务里记录实测体积
- **微信改版**：OCR 依赖的是屏幕上的**文字**而不是控件结构，比节点方案更抗改版；规则集中在 `PaymentPageRules` 与纠错表里
- **HyperOS 冻结后台服务**：同一个既有风险。这次因为多了 OCR，「服务还活着但收不到事件」时表现为不弹窗，不会产生错误数据
- **截图能力在部分 ROM / 关闭无障碍截屏权限时不可用**：`takeScreenshot()` 返回错误码时静默降级为「微信不识别」，并在设置页显示 OCR 不可用状态，绝不假成功
