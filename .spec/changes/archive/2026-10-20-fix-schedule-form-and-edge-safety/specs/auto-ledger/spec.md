# Delta：auto-ledger

## ADDED Requirements

### Requirement: 支付结果页不参与入账
系统 MUST NOT 把「支付成功 / 付款成功 / 交易成功」这类**支付结果页**当成账单详情页入账。

结果页判据 MUST 同时满足：

- 页面命中成功类状态词（`支付成功` / `付款成功` / `交易成功` / `支付完成` / `付款完成`）
- **没有**账单标题（`账单详情` / `交易详情` / `余额明细详情` / `账单明细` 等）
- **没有**任何交易单号（`交易单号` / `商户单号` / `商家订单号` / `转账单号` / `订单号`）
- **没有**任何账单时间字段（`支付时间` / `收款时间` / `交易时间` / `转账时间` / `创建时间`）

任一条件不满足就 MUST NOT 判为结果页。

> 依据：2026-10-20 真机，一笔 20.00 元支付宝付款先出现「付款成功（聚合收款）」页、
> 随后出现「支付成功」页；后者能凑够「付款方式 / 当前状态」两个强字段，因此被当成账单详情页
> 又识别了一次。结果页不入账之后，同一笔付款只在真正带账单信息的那一页触发。
>
> 判据保守的原因：支付宝旧版账单详情页在 25 张样本里有 21 张不渲染交易单号，
> 若只按「无单号」排除会大面积漏记；它们一定有「支付时间」，所以用时间字段作为放行依据。

#### Scenario: 支付宝支付成功页不弹窗
- GIVEN 页面文本为「支付成功 / ¥20.00 / 某人工智能公司 / 付款方式 / 账户余额 / 当前状态 / 完成」
- WHEN 识别流程执行
- THEN 判为支付结果页
- AND 不出现确认悬浮窗
- AND 识别日志记录「支付结果页，不入账」

#### Scenario: 结果页带交易单号仍按账单入账
- GIVEN 微信页面为「当前状态 / 支付成功 / ¥25.50 / 瑞幸咖啡 / 交易单号 4500…」
- WHEN 识别流程执行
- THEN 正常判为账单详情页并弹窗

#### Scenario: 旧版账单不因缺单号被误杀
- GIVEN 支付宝旧版账单页为「账单详情 / 天猫 / 支出25元 / 交易成功 / 支付时间 2026-10-19 18:01:22 / 付款方式」
- WHEN 识别流程执行
- THEN 仍判为账单详情页并弹窗

#### Scenario: 同一笔付款跨两页只记一次
- GIVEN 一笔付款在「聚合收款」与「支付成功」两页先后出现
- WHEN 两页先后被识别
- THEN 结果页不触发
- AND 账单页最多弹一次确认
