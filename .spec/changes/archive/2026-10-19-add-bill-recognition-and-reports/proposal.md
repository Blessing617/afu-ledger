# 变更：账单页识别修复 + 报表/日历 + UI 重塑

## 动机

当前自动记账在真机上有三个实际故障，用户体感统一为「识别坏了」：

1. **支付宝「我的」页被误判成支付页**。真机实测：停在支付宝「我的」页时弹出确认卡片，金额 `¥25.00`、
   商户名取到了页面广告文案「放心消费在身边」。原因是判定只要求「弱交易词命中 2 个」，
   而「我的」页含「账单」「交易」等词。
2. **忽略后卡片立刻重新弹出**。去重指纹是「包名 + 金额 + 商户名」，商户名由 OCR 现猜、每帧可能不同；
   且指纹只存内存、60 秒过期。卡片又在显示期间把后续识别全部节流（`throttled OVERLAY_SHOWING`），
   于是一张没关掉的卡片会让整个自动记账看起来彻底失效。
3. **发布版根本不识别账单页**。`PaymentPageDetector` 里的账单规则被 `allowDebugRules` 挡住，
   只有 debuggable 构建才认「账单详情」。用户要的正是「账单页点进去就能识别」，
   所以这条限制与需求直接冲突。

另外用户明确需要：把支付过程（支付成功结果页）的内容暂时放下，只保证**账单页**能识别，
并且要能区分是支付宝还是微信；同时补齐实用功能（报表、日历）与二次元圆润的 UI。

## 范围

在范围内：

- 识别目标收敛为「账单详情页」：金额、商户、来源应用（支付宝 / 微信）、交易单号
- 页面判定收紧：主界面 / 我的页 / 列表页必须被排除；账单页必须有专属字段作强证据
- 去重改为「交易单号优先」的指纹，并持久化（含用户主动忽略的指纹）
- 悬浮窗生命周期：忽略即关、离开页面或切走应用自动关、60 秒超时
- 识别速度：账单页从页面稳定到悬浮窗可见 ≤ 350ms
- 新增报表页：月度/年度收支、分类占比与排行、每日趋势
- 新增日历视图：首页月历 + 按日筛选
- 分类图标：更完整的图标集 + 每个分类固定柔和底色，分类管理页可选择图标
- 主题色板与背景图选择区的版式修复（8 色居中网格）
- 二次元圆润视觉与动效统一

不在范围内：

- 支付成功结果页的字段解析精度（保留现有识别，但不再是验收对象）
- 多账本、云同步、导入导出、预算（本期不做）
- 喵喵记账里的广告位、SVIP、喂养玩法，一律不做
- 数据库 schema 变更（指纹走 DataStore，避免迁移风险）

## 方法

1. 重写 `PaymentPageRules`：分成「账单页强字段」「列表页/主界面排除词」「金额排除」三组，
   判定顺序固定为「排除 → 强证据 → 金额唯一」。
2. `PaymentDraft` 增加 `tradeNo`（交易单号）与 `source`（明确的应用标签）；
   指纹 = `包名|交易单号`，无单号时退化为 `包名|金额|商户|日期`。
3. 新增 `ProcessedBillStore`（DataStore）：记录已提示与已忽略的指纹，7 天过期。
4. `PaymentConfirmController` 在命中前查指纹库；忽略时立即写入；页面离开时隐藏。
5. UI 侧新增 `ui/report/` 与 `ui/home/CalendarStrip.kt`，图表全部用 Canvas 绘制，
   不引入图表库（离线、包体、动效可控）。
