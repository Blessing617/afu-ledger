# 变更：背景图首帧就位 + 大背景下的滚动预算

## 动机

真机试用反馈两条，都发生在「设置了自定义背景图」之后：

1. **打开 / 切回来时背景图有明显的加载延迟。** 首帧只有主题底色，图片要等一次异步解码才淡入 —— 观感就是「打开先白一下」。原实现按**原始分辨率**解码（相册照片常见 4000×3000），解码更慢；而 1440×3200 的 ARGB 位图约 18MB，Coil 默认内存缓存只有可用内存的一小部分，冷启动时命中率低，于是每次都要重新解码。
2. **快速上下滑动时的流畅度还有余量。** 大背景图常驻为一张大纹理，内容每帧变化时要和它重新合成；半透明卡片越多，混合成本越高。

## 范围

在范围内：

- 背景图改为按屏幕像素解码（1:1，无可见画质损失）
- 预加载与界面显示共用同一内存缓存键
- 首帧用极小缩略图占位，缩略图在设置背景时生成、启动时自动补齐
- 淡入时长 200ms → 140ms
- 用 release 构建复测滚动帧预算（含 300 笔数据 + 大背景图）

不在范围内：

- 修改卡片视觉（半透明 / 描边 / 贴纸虚线）
- 改动列表数据结构或分页
- 图片裁剪 / 滤镜功能

## 方法

背景图请求统一由 `backgroundImageRequest()` 构建：`size = 屏幕像素`、`memoryCacheKey = "afu-background:<uri>"`，`BackgroundLayer` 与 `AfuApplication` 的预加载都走它。另外在设置背景图时用 `BitmapFactory` 生成一张 96px 宽的 JPEG 缩略图存到 `files/background_thumb.jpg`，启动时若缺失则补生成；`BackgroundLayer` 在第一帧就把这张缩略图铺上（解码几毫秒），原图到达后淡入覆盖。
