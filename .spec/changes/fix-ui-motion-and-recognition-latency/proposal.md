# 变更：修复记账转场遮挡、自动记账识别延迟与设置页滑动卡顿

## 动机

用户在小米 14 Pro 上日常使用后反馈四个问题，都不是「功能缺失」而是**已有功能的质量问题**：

1. **点「记一笔」有明显动画错误，被「还没有记账」挡住**
   记账表单滑入时，空状态卡片（「还没有记账」）与悬浮按钮画在表单之上。根因是层级 bug：三个底部标签页改为常驻组合后，可见标签页设了 `zIndex(1f)`，而承载二级页面的 `NavHost` 没有设 zIndex（默认 0f），于是标签页内容反而盖住了二级页面。转场期间表单被穿透看到，观感上就是「动画错了」。

2. **微信自动记账要等很久才弹窗**
   一次识别串了太多环节：600ms 去抖 → 截全屏 → 把 HardwareBuffer 拷成 ARGB_8888 → 纯 Kotlin 逐像素双线性插值缩到 960 长边（全屏约 42 万输出像素 × 12 次采样）→ det 推理 → 每个文本行串行 rec 推理。而且**没有任何快速预判**：聊天页也要白跑一次完整 OCR 才判定失败。首次启用还要再叠加 16MB 模型解压与两个 ORT session 加载。

3. **支付宝快一点但也不够快**
   支付宝走无障碍节点，本该很快，却同样吃 600ms 固定去抖，且继续受节流间隔约束。对比手机上「喵喵记账」的体感，这里明显慢。

4. **设置页上下滑动卡顿**
   自动记账区块内有一个「每 5 秒刷新」的 `rememberKeepAliveState`，它会让包含十几个 FilterChip 的整块周期性重组；同时三个标签页常驻组合，alpha=0 的页面仍在组合树中，叠加背景模糊与半透明卡片。

## 范围

在范围内：

- **把「记一笔」从整页滑入改为居中对话框**，与「新增账户」统一交互语言（用户明确要求：以添加资产的体验为基准）
- 修掉二级页面被标签页遮挡的层级 bug（问题 1，根因修复而非调参）
- 缩短识别链路的总延迟：去抖自适应、OCR 预处理改用系统能力、截图帧不再被丢弃、退避不拦用户主动点击（问题 2、3）
- 把识别各阶段耗时做成可观测数据，写进识别日志（支撑问题 2、3 的验收）
- 消除设置页的周期性无效重组，并处理卡片半透明导致的滑动观感问题（问题 4）
- 更新主规格中对应的响应预算与动效约束

不在范围内：

- 把「新增账户」改成整页（用户已选定额，以资产为基准，不动资产侧）
- 更换或重新训练 OCR 模型（PP-OCRv4 移动版保持不变）
- 引入量化模型、多线程 rec 并行到改变模型行为的程度
- 改变去重语义、金额解析规则、页面判定特征词
- 新增 `INTERNET` 或任何网络能力（硬性红线不变）
- 引入基线档案（Baseline Profile）、Compose compiler 指标驱动的全量重构
- 修改「喵喵记账」本身或做逐帧对比
- 处理 `keep-auto-ledger-alive-on-hyperos` 变更遗留的 HyperOS 保活问题（那是另一个变更）

## 方法

按「根因优先」推进，四个问题各自定位到确定的代码缺陷后动手：

1. **交互统一（用户追加要求）**：「记一笔」由整页导航改为居中对话框，与「新增账户」同形；顺带彻底消除了二级页面被标签页遮挡的层级问题——对话框是独立窗口，不受 zIndex 影响。
2. **OCR 延迟**：把逐像素缩放换成 `Bitmap.createScaledBitmap` 之类的系统路径，只在检测网络实际输入尺寸上做归一化；截图帧到手后立即消费，不因后续事件丢弃；退避只作用于「非用户主动」的路径；按页面类型自适应去抖。
3. **支付宝**：缩短已判定为支付页时的去抖，节点路径不引入任何截图开销；用分段耗时日志对比两条通道。
4. **设置页卡顿**：把 5 秒刷新从「整块重组」改为只让一行状态文本重组的独立状态读取，并让不可见标签页停止定时器。

每一项都以真机可测的数字验收（`dumpsys gfxinfo`、识别日志里的分段耗时），而不是「感觉快了」。

## 已确认

- **新增类操作的统一形式：以「添加资产」为基准，即居中对话框 + 遮罩。** 记账表单改为对话框；资产侧不动。
- **一切以真机实测为准**：由实施方自行用小米 14 Pro 测试决定效果，用户只做中途抽检。
