# 变更：记账体验打磨与支付页识别恢复

## 动机

一整天真实使用后暴露出一批「用起来别手」的问题，集中在三处：

1. **无法整理的列表**：资产账户建好后顺序固定，想把自己常用的账户排到前面只能删了重建。
2. **改不动的表单**：预算管理页的编辑器是 Material 表单堆，视觉上和「记一笔」完全两套语言；
   更严重的是编辑已有预算时金额带着千分位逗号，解析失败导致保存按钮永远灰着——用户改不了自己的预算。
3. **过度保守的识别**：10-20 为修复「同一笔付款在两个页面各记一次」，把支付结果页（付款成功 / 支付成功）
   整个排除出识别范围。结果是从「偶尔重复」变成「支付过程中完全识别不到」，只剩点进账单详情页才弹窗。

同时还有一批细节：记一笔面板容易误触遮罩退出、删除键不能连按、`00` 键多余、日期和备注在面板里出现两份、
弹出不够 Q 弹；金额输入把「整数位数 + 小数位数」当成总位数上限，`446.22` 只能输 5 个数字；
资产页把账户余额缩写成 `4.70万` 而不是完整金额——大额显示问题应该由布局（缩字号、折行）解决，
而不是用单位把数字藏起来；净资产点按也不该是「展开更多数字」，而应是一键隐私遮罩。

本变更按「先修正确性、再统一视觉、最后恢复识别」的顺序处理，并把改动提交到 GitHub 发新版本。

## 范围

在范围内：

- 资产账户长按拖动排序（含记账面板账户顺序跟随、备份迁移保留）
- 资产页金额改为全部完整显示（布局自适应，不用单位缩写），并支持一键隐私遮罩 `¥••••`（账户行 `•••`，状态持久化）
- 预算管理页：修复编辑后保存不可用；编辑器改为与记一笔同款的底部面板
- 定时记账：编辑器分区重排、字段收敛、列表卡片信息层级重排
- 记一笔面板：金额位数、键盘精简、删除键连按、备注输入、退出方式、弹簧手感
- 金额输入与展示的全量排查（记账 / 资产 / 预算 / 定时记账 / 报表 / 历史 / 识别弹窗）
- 支付结果页恢复参与识别，并与账单详情页做同笔去重
- 版本号递增、GitHub 提交、tag 与 Release APK 附件
- 动手前导出一次真实数据备份（用户在用真实账本，不可丢）

不在范围内：

- 不引入云同步、账号体系或任何网络权限
- 不改自动记账的无障碍授权、保活、OCR 引擎选型
- 不重做主题系统、背景图与图标体系
- 不改报表的图表形态与统计口径
- 不为「支付结果页识别」新增独立开关（默认即按本变更规则工作）

## 方法

先用 delta 规格把六块行为定死，再按「金额规范 → 记一笔 → 资产 → 预算 → 定时记账 → 识别 → 发布」的顺序实施。
预算与定时记账不重写业务逻辑，只重做编辑器外观与字段组织，并复用记一笔已有的控件（大字号金额、
胶囊分段、圆形图标格、步进器、底部胶囊主按钮）。识别侧保留全部既有强证据判定，只把结果页从
「直接丢弃」改为「可识别来源」，把去重责任交给已有的会话去重（同包名 + 同金额 + 同方向 + 时间窗）。
