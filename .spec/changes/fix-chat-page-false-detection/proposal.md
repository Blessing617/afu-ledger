# 变更：聊天页不再误触发识别 + 常驻通知文案简化

## 动机

两件事：

1. **记录完一笔 27.00 之后，点开与好友的聊天界面又弹了一张卡片，金额是 2700。**

   聊天页里并没有转账 / 收款卡片，也没有成功状态词 —— 所以「排除词表」这条路根本拦不住它：
   页面缺账单字段，又被当成「支付结果页」放行，聊天正文里的 27.00 被 OCR 读成 2700。
   识别日志留证（另一次同类误弹）：`14:45:35 支付结果页,可入账 · ¥9.00 · 某好友-好友B · 时间回退`。
   昨天那笔 3.50 被记成多笔，也是同一类「短页面 + 没有单号 + 没有账单时间」的漏口。

2. **常驻通知的副标题没有意义。** 用户明确说：「识别微信、支付宝页面」这行不用，
   通知上只写「阿福自动记账运行中」就行。

## 范围

在范围内：

- 给识别加**一级排除**：命中「聊天 / 会话页」证据时直接放弃，先于结果页与账单页的准入判定
- 强化聊天证据：不靠空格（OCR 空格不稳），补「转账给 / 消息已发出」这类聊天专属词
- **结构判据**：支付结果页的金额 MUST 是「全页字号峰值」（用 OCR 行高判断）。
  聊天正文里的数字与正文同高，这条正是为了挡住词表拦不住的聊天页
- 拦住「OCR 丢小数点」：结果页上只有整数、没有小数点的金额一律放弃识别（宁可漏记，不记错 100 倍）
- 识别日志在命中时额外记录**页面文本前几行**（截断、去隐私），下次再出现误识别能直接看到真实文本
- 常驻通知标题改成「阿福自动记账运行中」，去掉「识别微信 / 支付宝支付页…」那行

不在范围内：

- **不改**「无交易单号页面」的指纹退化规则（上次已明确不动）；本次不动去重逻辑
- 不改识别延迟、OCR 通道、悬浮窗样式
- 不新增「聊天页里主动识别转账」的功能（聊天里的转账消息本来就该忽略）

## 方法

`PaymentPageDetector` 的判定顺序里，在最前面加一步：

```
① 强排除词 → ② 聊天/会话页（一级排除） → ③ 列表页 → ④ 主界面 → ⑤ 结果页 → ⑤.5 字号判据 → ⑥ 账单页准入
```

聊天证据分两类：

- **输入栏类**（改为去空白后匹配）：`按住说话` `语音输入` `发送消息` `聊天信息`
- **聊天专属**（新增）：`转账给` `消息已发出` `对方正在输入` `撤回了一条消息` `拍一拍`

> 注意：`微信红包` / `微信转账` **不能**进词表 —— 微信红包领取页自己就写着「微信红包」，
> 加进去会把真实的红包页误杀（真机回归用例当场就挂）。

「转账给」在真正的转账账单详情页里也会出现，所以命中聊天证据时再看一眼强字段：
页面同时有 ≥2 个账单专属字段就继续识别。

**字号判据**：`PageText` 增加 `height`（OCR 通道填真实行高，节点通道为 0 表示未知），
结果页命中金额后比较「金额行高度 vs 其它行高度中位数」，低于 1.5 倍即放弃识别并记日志
`金额不是页面上最大的字`。拿不到行高时跳过这条判据，不用「猜不到」去否掉识别。

日志侧：`PaymentDraft` / `RecognitionEntry` 增加 `pageHeadline`（页面前 3 行、每行 24 字、总长 ≤96），
命中时写入，设置页日志里单独一行显示。
