# 任务

## 1. 诊断与复现（先证伪，再动手）

- [ ] 1.1 冻结发生时抓进程状态：`adb shell dumpsys activity processes | grep -A3 afu.ledger`，记录 `frozen=` 与 `adj=` — 验证：拿到冻结前/冻结后的对比数据
- [ ] 1.2 确认授权未丢失：`adb shell settings get secure enabled_accessibility_services` — 验证：输出中仍包含本服务组件名
- [ ] 1.3 排除崩溃与 ANR：`logcat` 搜索 `has died` / `ANR in com.afu.ledger` — 验证：复现窗口内无相关记录
- [ ] 1.4 把诊断结论（是否为进程冻结）写回 `design.md` 的根因段落 — 验证：文档含实测数据而不是推测

## 2. 前台服务与常驻通知

- [ ] 2.1 Manifest 声明 `FOREGROUND_SERVICE`、`FOREGROUND_SERVICE_SPECIAL_USE`、`POST_NOTIFICATIONS`，服务加 `foregroundServiceType="specialUse"` 与用途 `<property>` — 验证：合并 Manifest 含声明且**不含** `INTERNET`
- [ ] 2.2 服务连接后启动前台服务，使用 `IMPORTANCE_LOW` 通知渠道（无声、不弹横幅）— 验证：通知栏出现常驻项且无声音
- [ ] 2.3 服务断开/销毁时停止前台服务并移除通知 — 验证：关闭无障碍服务后通知消失
- [ ] 2.4 Android 13+ 运行时请求 `POST_NOTIFICATIONS`，拒绝时功能不崩溃 — 验证：拒绝后自动记账仍可用，设置页出现提示

## 3. 事件心跳与状态模型

- [ ] 3.1 服务内维护 `lastEventAt`，任何受支持应用的事件都更新它 — 验证：识别日志中可看到更新时间戳
- [ ] 3.2 定时检查断流：超过 30 分钟无事件置为「疑似冻结」— 验证：人为停止事件来源后状态能变为疑似冻结
- [ ] 3.3 把「前台服务是否在跑 / 最近事件时间 / 疑似冻结」暴露为可观察状态供设置页读取 — 验证：设置页显示值与真实情况一致，不写死

## 4. 设置页展示与恢复入口

- [ ] 4.1 自动记账区块展示三态：运行中 / 疑似被系统冻结 / 后台保护未开启 — 验证：三种状态都能在真机上复现展示
- [ ] 4.2 「疑似冻结」时提供一键跳转无障碍设置 — 验证：点击后进入系统无障碍页
- [ ] 4.3 通知权限被关闭时展示降级提示 — 验证：关闭通知后设置页出现「会降低后台可靠性」
