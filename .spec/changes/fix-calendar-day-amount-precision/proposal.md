# 变更：明细页月历每日金额完整显示

## 动机

明细页月历每天都标一个净额，但这个数字被缩写掉了：

- 金额 ≥ 10000 元时变成「k」，而且是**整数除法**：当天收入 17,165.50 元（1716550 分）
  显示成 `+1k`，真实数额完全读不出来。
- 金额 ≥ 100 元时直接丢掉小数部分（`abs / 100` 截断而非四舍五入）：
  163.45 元显示成 `-163`。

结果是用户看到日历上的数字和明细列表对不上，误以为记账**丢数据**了。

这与资产页早已确立的原则冲突——`.spec/specs/assets/spec.md`：

> 所有金额 MUST 完整显示（千分位 + 两位小数）……MUST NOT 使用「万 / 亿 / 万亿」缩写，
> MUST NOT 使用 `w / k / m` 之类的英文单位……金额完整显示的实现 MUST 由布局负责，而不是由数值格式负责。

月历格子小，所以当时偷了懒；正确做法和资产页一致：**数字保持完整，由字号与折行适配格子**。

## 范围

在范围内：

- 明细页月历格子里每日净额的显示（完整数字 + 自适应字号 + 极端长度折行）
- 金额格式化工具新增「带符号的完整金额」方法，并删掉月历私有的缩写实现
- 单元格高度与排版调整（数字与金额两行不重叠、选中态仍可读）
- 单元测试覆盖大额 / 带小数 / 负数的格式化
- 版本号升级、release 构建、GitHub Release 与真机覆盖安装

不在范围内：

- 首页今日卡片、报表页、交易行金额（这些本来就完整）
- 月历的交互（切月、回到今天、点选筛选）与数据来源
- 数据库结构、交易数据本身、备份格式
- 用图钉 / 圆点替代金额的形态改动（本次只修「显示不全」）

## 方法

把月历格子里的金额改成与其它页面一致的完整金额（符号 + 千分位 + 两位小数），
再用「先按格子可用宽度测量、取能完整放下的最大字号」代替现在按长度硬编码的缩写分档；
字号下限 6sp，极端长度（万亿级）允许折成两行，绝不裁切、绝不省略号。
格子高度由 46dp 提到 52dp 以容纳两行文本。
