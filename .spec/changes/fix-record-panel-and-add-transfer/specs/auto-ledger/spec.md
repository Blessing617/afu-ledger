# Delta：auto-ledger

## MODIFIED Requirements

### Requirement: 去重
系统 SHALL 对同一笔账单只请求一次确认；重复的页面事件或服务重复回调 MUST NOT
产生第二次确认或第二笔交易。

去重 MUST 有两层，且第二层必须能跨页面生效：

1. **指纹层**（长期）：由 [交易单号指纹与持久化去重] 定义，用于「忽略过 / 入账过」的账单在有效期内不再打扰。
2. **会话层**（短窗口）：同一来源包内，**金额相同、方向相同**的命中在
   `SESSION_WINDOW`（默认 120 秒）内视为同一笔，即使两次命中的指纹不同。
   这层存在的唯一理由：同一笔付款在支付宝里会依次出现两个页面
   （「聚合收款 / 付款成功」与「支付成功」），两页的商户与单号字段并不一致。

会话层的**例外**：两次命中都解析出非空、且互不相同的交易单号时，MUST 视为两笔不同交易。
只要有一方单号为空，就 MUST 按会话层合并。

去重指纹 MUST NOT 包含**由页面文本猜出来的商户名**：真机实测同一张账单两次 OCR
会把商户名读成 `阿佑鲜烫牛內米线` 与 `阿佑鮮烫牛内米线`（简繁/形近字差异），
带进指纹就变成两个指纹，同一张账单反复弹窗。商户名只用于展示。

代价是「同一分钟内给两家不同商户付了相同金额」会被合并成一次确认 —— 该场景罕见，
且用户仍可手动补记。

**确认按钮 MUST 只入账一次。** 一次浮窗展示期间，用户连点「记一笔」MUST NOT 产生两笔交易：
点击后 MUST 立即置为进行中并忽略后续点击，直到入账返回或浮窗收起。

#### Scenario: 页面反复刷新不重复弹出
- GIVEN 用户停留在账单详情页，页面事件被多次触发
- WHEN 同一笔账单在同一时间窗内被再次识别
- THEN 不出现第二个悬浮窗
- AND 最多只产生一笔交易

#### Scenario: 商户名读错不影响去重
- GIVEN 同一张账单第一次识别出商户「阿佑鲜烫牛內米线」，第二次识别出「阿佑鮮烫牛内米线」
- WHEN 两次识别完成
- THEN 两次得到同一个指纹
- AND 只弹一次确认

#### Scenario: 同金额不同分钟视为两笔
- GIVEN 同一商户先后有两笔 17.00 元，账单时间分别为 17:59 与 18:01
- WHEN 两次识别完成
- THEN 各自弹出一次确认，互不去重

#### Scenario: 支付宝一笔付款跨两个页面只记一次
- GIVEN 用户完成一笔 20.00 元支付宝付款
- AND 先停在「付款成功（聚合收款）」页：该页有交易单号，但商户字段缺失
- AND 随后停在「支付成功」页：该页无交易单号，但有商户名
- WHEN 两个页面先后被识别（间隔在会话窗口内）
- THEN 只出现一次确认
- AND 只产生一笔 20.00 元支出
- AND 该笔的备注是商户名，而不是「未识别到商户」

#### Scenario: 两个页面都缺单号也只记一次
- GIVEN 同一笔付款的两个页面都不渲染交易单号
- WHEN 两次识别先后完成
- THEN 两次命中落在同一会话层
- AND 只产生一笔交易

#### Scenario: 两个页面单号不同视为两笔
- GIVEN 两次命中都解析出非空且互不相同的交易单号
- WHEN 第二次识别完成
- THEN 系统按两笔处理，各自弹一次确认

#### Scenario: 同额同向的两笔真实消费不被误合并
- GIVEN 用户在 60 秒内先后买了两瓶水，各 2.00 元，两笔都有各自的交易单号
- WHEN 两次识别完成
- THEN 两次都弹确认（因为两个单号都非空且不同）

#### Scenario: 连点确认只入账一次
- GIVEN 确认浮窗显示一笔 3.50 元支出
- WHEN 用户在短时间内连续点击「记一笔」两次
- THEN 只产生一笔 3.50 元交易
- AND 浮窗收起后不再重复入账

### Requirement: 交易单号指纹与持久化去重
系统 SHALL 以「交易单号」作为同一笔账单的**长期**主指纹，并持久化「已提示」与「已忽略」两种状态。

**短窗口内的同一笔判定 MUST 由 [去重] 的会话层负责**，指纹层不再承担「挡住紧接着的第二次命中」的职责：
单号缺失或两页单号不一致（一有一无）是支付宝的常态，只靠指纹会漏掉跨页重复。

**系统 MUST NOT 通过模拟点击（如展开「更多」）来获取交易单号**：账本应用不得操作用户的其他应用界面。

无交易单号时，指纹 MUST 退化为「包名 + 金额 + 方向 + 账单时间」。
其中账单时间 MUST 使用解析出的账单时间而不是识别时刻 —— 支付宝的**旧版**账单详情布局
不渲染交易单号（25 张样本里有 21 张属于旧版），退化指纹是这个场景下的常态，
用它才能区分同商户同金额的不同笔。

单号字段的标签集 MUST 至少包含：`交易单号`、`商户单号`、`商家订单号`、`订单号`、**`转账单号`**。
微信的转账类账单用的正是「转账单号」，漏掉它会让转账类账单全部退化。

用户主动忽略或确认过的指纹 MUST 在 7 天内不再触发确认；指纹记录 MUST 仅存于本机。

#### Scenario: 支付宝无单号时按账单时间退化去重
- GIVEN 支付宝账单页不提供交易单号，账单时间为 2026-10-19 18:01:22，金额 2500 分，商户「某餐饮店」
- WHEN 用户忽略后再 10 秒重新打开同一张账单
- THEN 不出现确认悬浮窗

#### Scenario: 同商户同金额不同分钟视为两笔
- GIVEN 同一商户先后有两笔 17.00 元，账单时间分别为 17:59:40 与 18:01:22
- WHEN 两次识别完成
- THEN 各自弹出一次确认，互不去重

#### Scenario: 确认过的账单不重复入账
- GIVEN 用户对交易单号为 B 的账单点过「记一笔」
- WHEN 用户再次打开该账单
- THEN 不出现确认悬浮窗

#### Scenario: 不模拟点击对方界面
- GIVEN 支付宝账单页的交易单号需要展开「更多」才可见
- WHEN 识别流程执行
- THEN 系统不对支付宝界面执行任何点击操作
- AND 按退化指纹去重

### Requirement: 识别结果的可观测性扩展
系统 SHALL 在识别日志中记录足以复现判断的字段：方向、账单时间、以及「时间是否回退」标记、
本次使用的去重指纹，MUST NOT 记录完整页面原文。

**识别日志 MUST 落盘保存，进程重启后仍可查看。** 记录在应用私有存储里，环形保留最近
200 条 / 7 天，超出即淘汰；写盘 MUST NOT 阻塞识别主流程（丢了日志也不能拖慢弹窗）。
「昨天出现的好几笔重复」必须能在第二天还查得到，否则日志只剩排查价值为零的当下现场。

- 每条记录 MUST 至少包含：时间、来源应用、结果（弹窗可见 / 已入账 / 用户忽略 / 超时 / 失败原因）、
  金额、商户、时间来源标记、去重指纹
- 日志内容 MUST NOT 包含整页文本、账号、头像等与本机账本无关的信息
- 设置页 MUST 能查看最近日志、清空日志；清空 MUST 立即落盘生效

#### Scenario: 日志能区分方向与时间来源
- GIVEN 识别日志开关已开启
- WHEN 完成一次识别
- THEN 该条日志包含方向（收入/支出）与账单时间
- AND 时间来自回退时该条标注「时间回退」

#### Scenario: 重启后还能看到昨天的重复记录
- GIVEN 昨天识别过同一笔 3.50 元，弹了两次确认
- WHEN 用户今天重新打开应用并查看识别日志
- THEN 两条记录仍然在，且能看出它们的指纹是否相同
- AND 不需要用户昨天提前打开日志开关才有记录
