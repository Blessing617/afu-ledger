# 变更：修好「记一笔」失效、识别重复与弹窗遮罩不一致，并新增资产转移

## 动机

四个真实问题，其中前三个是用户在实际使用中撞到的：

1. **「记一笔」点了没反应。** 用户做了一次资产转移（工资卡转出 5565.21 到消费卡，用一笔支出模拟），
   保存后中央记账按钮就彻底失效——点击后没有任何界面变化。重启应用即恢复，说明是内存里残留的状态。
2. **同一笔小额被记了多笔。** 买水支出 3.50 元出现了好几笔，备注显示成微信好友名（个人收款码）。
   这类页面没有交易单号、也没有账单时间，指纹退化成「包名 + 金额 + 方向 + 分钟」，
   时间取的是识别时刻，于是同一笔在不同分钟再被识别一次就成了新指纹。
3. **预算编辑面板背后的遮罩比定时记账深一截。** 两个面板都画了同档遮罩（黑色 32%），
   但预算面板是 `Dialog` 且没有关掉系统对话框自带的 dim，于是两层叠在一起，看起来黑了一层。
4. **没有资产转移。** 现在只能在两个账户各记一笔支出/收入来模拟，结果报表里凭空多出一大笔支出和收入，
   当月收支与分类占比全被污染。

## 范围

在范围内：

- 修复记账面板在保存/删除后无法再次打开（以及连带的上次输入残留、重复提交）
- 修复确认浮窗连点导致重复入账；指纹退化规则**本次不动**（按天去重会让「一天内两次同样金额」少提示一次，副作用比收益大），
  改为把识别日志落盘，下次真出问题能拿到指纹证据再决定
- 修复预算编辑面板的系统 dim 叠加（弹层遮罩只有一层）
- 新增「资产转移」：记账面板里的第三档「转账」，一笔进出两个账户，不计入收支统计
- 识别日志落盘，进程重启后仍可查看（否则「昨天那几笔」永远查不到）
- 数据库版本 +1，转移到备份格式，升级不丢数据
- 出 release、装到真机、推 GitHub

不在范围内：

- **改指纹退化规则**（按天去重）：本次显式放弃，等日志攒到真实样本再谈
- 自动识别微信/支付宝的「账户内转移」（零钱充值、银行卡到账），仍然需要手动记
- 多币种、转账手续费、跨币种汇率
- 识别日志的导出/分享（只在设置页内查看与清空）
- 转账的定时重复（定时记账暂不支持转账类型）

## 方法

**记账面板失效**：面板的 ViewModel 挂在 Activity 的 ViewModelStore 上，key 固定为 `record-new`。
`save()` 把 `finished` 置 true，`RecordScreen` 观察到就跑关闭动画；面板关掉后 ViewModel 并不销毁，
下次打开拿回同一个实例，`finished` 初始就是 true，于是刚组合就立刻关闭——表现就是「点了没反应」。
修法是让完成态成为**一次性事件**，并在每次打开时重置输入，而不是让它留在 ViewModel 的状态里。

**重复入账**：确认动作加进行中闸门，一次弹窗只允许提交一次；指纹规则这轮不动，
但识别日志改为落盘（最近 200 条 / 7 天），下次出现重复时能直接看到两条命中用的是不是同一个指纹。

**遮罩**：预算面板补上与定时记账一致的 `window.setDimAmount(0f)`，并把这套做法收敛到一处，避免下一个面板再忘。

**资产转移**：交易表新增可空列 `transferAccountId`，`type` 新增 `TRANSFER`。
一笔转账 = 单条记录（转出账户 + 转入账户 + 金额），余额查询把「转出扣、转入加」算进去，
报表与预算按 `type` 天然排除。这条路线与 Actual Budget 的 transfer payee、
My Expenses 的 `TransferTransaction` 一致：单条记录、两个账户、天然配对，不会出现「只删了半边」。
