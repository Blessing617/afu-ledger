# 设计：转场动效与背景图体验

## 一、动效重设计

### 1.1 层级模型

```
标签层（同级）        首页    资产    设置
                            ↕ 层级进入/返回
二级层                记账表单   分类管理
```

规则：

| 场景 | 方向 | 动效 | 时长 |
|---|---|---|---|
| 标签 ↔ 标签 | 水平（轻） | 淡入 + 12% 水平位移 | ≤ 200ms |
| 标签 → 二级 | 垂直（进入） | 从下方滑入 + 淡入 | ≤ 260ms |
| 二级 → 标签 | 垂直（返回） | 向下滑出 + 淡出 | ≤ 220ms |

### 1.2 为什么不再用「整屏平移」

当前实现两页各移动 50% 屏宽，视觉上是「两张卡片互相推挤」，缺少层级感，且在 60fps 边界上更容易掉帧（两页大面积重绘）。

新方案：新页只移动 **12% 屏宽**，旧页几乎不动（只淡出）。移动距离小，视觉上更像「浮上来」而不是「推过去」。

### 1.3 缓动曲线

- 统一用 `FastOutSlowInEasing`（Material 标准），或用 `spring(dampingRatio = 0.85f, stiffness = MediumHigh)`
- **禁止**默认线性 `tween`
- 进入比退出略长（进入 200/260ms，退出 180/220ms），符合「进入有仪式感、退出要利落」

### 1.4 系统关闭动画时退化

沿用既有 `rememberMotionEnabled()`：为 false 时用 `snap()`。

## 二、背景图恢复原分辨率

### 2.1 硬约束

用户明确要求**不得降采样**，所以上一版「按 720×1600 解码」的方案回退，改为原图解码。

### 2.2 性能回收手段（按优先级）

| 手段 | 原理 | 预期收益 |
|---|---|---|
| **合并遮罩层** | 现在「背景位图 + 全屏半透明遮罩」是两层全屏绘制；改成 `Modifier.drawWithContent` 里一次画完位图 + 叠色 | 少一层全屏合成 |
| **背景提升为独立硬件层** | `graphicsLayer` 缓存为 RenderNode，内容不变时 GPU 复用纹理 | 转场期间背景不重绘 |
| **淡入结束后固定 alpha** | 动画进行中 alpha 每帧变化会导致层失效；结束后置 1 让层可缓存 | 稳态下背景零重绘 |
| 转场期间背景静止 | 已满足（背景层在 NavHost 之外） | — |

### 2.3 验收目标

原分辨率 + 上述优化后，同操作下：

- p90 ≤ 12ms（当前原分辨率是 16ms，无背景是 7ms）
- jank < 2%

若达不到：优先保证「图片不模糊」，接受略高的 p90，并在 design 里记录实测值，不偷偷降分辨率。

## 三、取舍记录

| 方案 | 未选原因 |
|---|---|
| 降采样背景图 | 用户明确禁止，画质优先 |
| 转场时隐藏背景 | 会造成明显的背景闪断，体验更差 |
| 后台保活三个 tab | 与本次「动效自然度」目标不同，且内存代价大，留作独立变更 |
| 全局换成 View 体系 | 代价过大 |

## 四、待确认

1. 标签切换：纯淡入（最轻）还是淡入 + 12% 位移（有方向感）？
2. 二级页面进入时，背景是否轻微变暗（增强层级感，代价是多一层绘制）？
