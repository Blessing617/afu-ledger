# Delta：data-safety

## MODIFIED Requirements

### Requirement: 导出本地备份

系统 SHALL 允许用户把全部账本数据导出为单个备份文件，并保存到用户通过系统文件选择器指定的位置。

- 备份内容 MUST 包含：格式版本、导出时间、应用版本、账户（含初始余额、类型、颜色、图标、排序）、分类（含图标、颜色、排序）、交易（含金额、收支类型、分类、账户、备注、时间、来源）、定时规则（含周期、期次、结束条件、启用状态）。
- 备份格式 MUST 为 UTF-8 JSON，可被人直接阅读。
- 导出 MUST 流式写入，内存占用不随记录数增长：账户、分类、交易、规则逐表读取并写入，不得把整表一次性加载为 List。
- 备份文件 MUST NOT 包含任何设备标识、账号信息或无网络权限以外的隐私内容。
- 导出成功 MUST 展示文件保存位置与条数统计。

「归档状态」MUST NOT 再作为账户的备份字段出现 —— 归档概念已移除。旧的备份文件里若仍带该字段，
导入时 MUST 忽略它，MUST NOT 因为多出一个未知字段而整体拒绝。

#### Scenario: 导出全部数据

- GIVEN 账本内有 5000 笔交易、4 个账户、20 个分类、3 条定时规则
- WHEN 用户点「导出备份」并在系统选择器里选好位置
- THEN 生成 `.json` 备份文件
- AND 文件包含全部 5000 笔交易与其它实体
- AND 导出完成后提示「已导出 5000 笔交易」及文件路径

#### Scenario: 取消保存不产生空文件

- GIVEN 用户点「导出备份」
- WHEN 用户在系统文件选择器里按返回取消
- THEN 不创建任何文件
- AND 界面回到设置页且没有错误提示

### Requirement: 导入备份并还原

系统 SHALL 允许用户从备份文件还原账本数据。

- 导入 MUST 先校验文件格式与格式版本；不支持的版本 MUST 拒绝并说明原因，不得部分导入。
- 导入 MUST 在一个数据库事务内完成「清空现有数据 + 写入备份数据」，任一步失败则整体回滚。
- 导入 MUST 要求用户二次确认，并明确提示「现有数据将被替换，建议先导出当前数据」。
- 导入成功 MUST 展示还原的账户、分类、交易、规则条数。

- 旧备份文件中的账户「归档状态」字段 MUST 被忽略；导入后的账户 MUST 一律为普通（未归档）账户。
- 备份文件中的未知字段 MUST NOT 导致导入失败。

#### Scenario: 换机还原

- GIVEN 用户在新设备上装了同版本应用，账本为空
- WHEN 用户选择此前导出的备份文件并确认导入
- THEN 账户、分类、交易、定时规则全部出现
- AND 各账户余额与导出前一致
- AND 首页今日支出与导出前一致

#### Scenario: 旧备份里的归档账户被还原为普通账户

- GIVEN 一个旧版本导出的备份文件里带「已归档」账户
- WHEN 用户导入该备份
- THEN 该账户被还原并出现在资产页普通账户列表中
- AND 它的历史交易全部保留

#### Scenario: 版本不兼容被拒绝

- GIVEN 备份文件的格式版本号高于应用支持的版本
- WHEN 用户尝试导入
- THEN 提示「备份文件来自更新版本的应用，请先升级」
- AND 现有数据完全不变

#### Scenario: 文件损坏时回滚

- GIVEN 用户选择了一个被截断的 JSON 文件
- WHEN 用户确认导入
- THEN 解析失败并提示文件损坏
- AND 现有数据完全不变
