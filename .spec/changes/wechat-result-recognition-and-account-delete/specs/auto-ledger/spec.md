# Delta：auto-ledger

## MODIFIED Requirements

### Requirement: 确认悬浮窗
系统 SHALL 在识别成功后于当前页面之上展示确认卡片，包含金额、商户名（若有）、账户与分类选择，以及「记一笔」与「忽略」操作；用户确认前 MUST NOT 写入任何交易。

#### Scenario: 确认后入账
- GIVEN 悬浮窗展示金额 25.50、默认账户「现金」、默认分类「餐饮」
- WHEN 用户点击「记一笔」
- THEN 新增一笔 2550 分的支出交易
- AND 该交易的账户为「现金」、分类为「餐饮」、备注为识别到的商户名

#### Scenario: 当场修改分类
- GIVEN 悬浮窗已展示默认分类「餐饮」
- WHEN 用户改为「交通」并点击「记一笔」
- THEN 入账交易的分类为「交通」

#### Scenario: 忽略或超时丢弃
- GIVEN 悬浮窗已展示
- WHEN 用户点击「忽略」，或悬浮窗在 60 秒内未被操作
- THEN 悬浮窗消失
- AND 不产生任何交易

#### Scenario: 无可用账户时引导创建
- GIVEN 系统中没有任何资产账户
- WHEN 识别成功需要展示悬浮窗
- THEN 提示先创建资产账户，并提供跳转入口
- AND 不产生交易

### Requirement: 支付结果页参与识别且同笔只弹一次

系统 SHALL 把「支付成功 / 付款成功 / 交易成功」这类**支付结果页**视为可识别来源，
同时保证同一笔付款在结果页与后续账单详情页之间**只弹一次确认**。

**判定顺序 MUST 为：强排除 → 列表页 → 主界面/我的页 → 支付结果页 → 账单详情页正向准入 → 金额与方向。**

「支付结果页」判定 MUST 先于「账单详情页正向准入」执行。结果页成立时 MUST 直接产出确认，
MUST NOT 再要求页面命中账单标题或凑够 ≥2 个账单强字段 —— 微信支付成功页正是这种形态：
只有「支付成功 / ¥98.00 / 完成」，没有任何账单专属字段。

> 依据：10-21 恢复结果页识别时把结果页判定放在了正向准入之后。支付宝付款成功页自带
> 「当前状态」「付款方式」两个强字段，恰好过了准入；微信支付成功页一个都凑不出，
> 在准入这一步就被判「不是支付页面」，结果页规则永远执行不到 —— 真机表现就是「微信支付过程中不弹窗」。

**结果页判据** MUST 同时满足：

- 页面命中成功类状态词（`支付成功` / `付款成功` / `交易成功` / `支付完成` / `付款完成`）
- **没有**账单标题（`账单详情` / `交易详情` / `余额明细详情` / `账单明细` 等）
- **没有**任何交易单号（`交易单号` / `商户单号` / `商家订单号` / `转账单号` / `订单号`）
- **没有**任何账单时间字段（`支付时间` / `收款时间` / `交易时间` / `转账时间` / `创建时间`）

任一条件不满足 MUST NOT 判为结果页（它仍按账单详情页处理，走原有强证据判定）。

**结果页识别**：

- 命中结果页且能解析出唯一交易金额时 MUST 弹确认悬浮窗，MUST NOT 因为「不是账单详情页」而丢弃
- 方向 MUST 由成功类状态词判定；页面同时出现退款 / 收款类状态词时 MUST 判为收入，否则判为支出
- 结果页没有支付时间字段，`occurredAt` MUST 使用识别时刻，并在来源上标记为「识别时刻」
- 结果页没有商户名时 MUST 允许备注为空并正常弹窗，MUST NOT 因缺商户名放弃识别
- 弹窗 MUST 标明来源为「支付页」，使用户能看出它不是账单详情页
- 识别日志 MUST 记录「支付结果页，可入账」，MUST NOT 记录成跳过
- 结果页上「原价 / 优惠 / 立减 / 已省」等非实付金额 MUST NOT 参与金额唯一性判定
  （沿用既有的价格标签排除规则，本变更不改变该规则）

**同笔去重**（结果页与账单详情页之间）：

- 同一应用、同一金额、同一方向，且在会话窗口内先后命中的两页 MUST 视为同一笔，只弹一次
- 若两页都解析出交易单号且**不相同**，MUST 视为两笔，各自弹窗
- 结果页那笔已被确认入账或被忽略后，同一笔的账单详情页 MUST NOT 再弹窗，且 MUST NOT 修改已入账记录
- 结果页的确认悬浮窗仍开着时，同笔账单页的商户名、单号、页面时间 MUST 合并进**同一个**悬浮窗
  （信息更全的一次覆盖更弱的一次），MUST NOT 新开第二个悬浮窗，MUST NOT 产生第二笔交易

上述规则 MUST NOT 放宽既有的「主界面与列表页不触发识别」：非结果页的页面仍 MUST 通过
「账单页强证据判定」才允许识别。

#### Scenario: 支付宝支付成功页立即弹窗
- GIVEN 页面文本为「支付成功 / ¥20.00 / 某人工智能公司 / 付款方式 / 当前状态 / 完成」
- WHEN 识别流程执行
- THEN 判定为支付结果页并弹出确认悬浮窗
- AND 金额为 2000 分、方向为支出
- AND 弹窗来源显示为「支付页」
- AND 识别日志记录「支付结果页，可入账」

#### Scenario: 微信支付成功页无任何强字段也弹窗
- GIVEN 用户完成一笔 98.00 元微信支付并停在支付成功页
- AND 页面文本为「支付成功 / 某缴费平台 / ¥ 98.00 / 原价 ¥100.00 / 优惠 河南农信储蓄卡¥2.00 / 完成」
- AND 该页没有任何账单标题、交易单号与账单时间字段
- WHEN 识别流程执行
- THEN 判定为支付结果页并弹出确认悬浮窗
- AND 金额为 9800 分、方向为支出
- AND 原价 ¥100.00 与优惠 ¥2.00 不参与金额判定
- AND 弹窗来源显示「微信 · 支付页」

#### Scenario: 无强字段的极简支付成功页也弹窗
- GIVEN 页面文本只有「支付成功 / ¥25.50 / 瑞幸咖啡 / 完成」
- WHEN 识别流程执行
- THEN 判定为支付结果页并弹窗
- AND 金额为 2550 分、方向为支出

#### Scenario: 随后打开的账单详情页不重复弹窗
- GIVEN 结果页命中并弹窗后，用户在会话窗口内点进同一笔的账单详情页
- WHEN 账单详情页被识别
- THEN 判定为同一笔，不再弹出第二个悬浮窗
- AND 已弹窗的那笔不会被记成两笔

#### Scenario: 结果页已入账后账单页不再打扰
- GIVEN 用户在结果页弹窗里点了确认并入账
- WHEN 随后打开同一笔的账单详情页
- THEN 不出现新的确认悬浮窗
- AND 账本里只有一笔

#### Scenario: 两笔同金额仍各弹一次
- GIVEN 一分钟内连续两笔各 2.00 元付款，两页都带各自不同的交易单号
- WHEN 两次识别先后执行
- THEN 两次都弹窗
- AND 账本里有两笔

#### Scenario: 结果页缺商户名仍可记账
- GIVEN 结果页只有「支付成功 / ¥25.50 / 完成」而没有任何商户字段
- WHEN 识别流程执行
- THEN 正常弹窗，备注为空
- AND 用户确认后交易写入，金额 2550 分

#### Scenario: 主界面仍不误弹
- GIVEN 用户停在支付宝首页，页面上有历史通知「某餐饮店 付款成功 ¥25.00」
- WHEN 识别流程执行
- THEN 页面先被主界面判据排除
- AND 不弹出确认悬浮窗

#### Scenario: 支付成功页带交易单号时按账单页处理
- GIVEN 微信页面为「当前状态 / 支付成功 / ¥25.50 / 瑞幸咖啡 / 交易单号 4500…」
- WHEN 识别流程执行
- THEN 不判为结果页，按账单详情页识别并弹窗
- AND 交易单号被保留

#### Scenario: 旧版账单不因结果页规则被误判
- GIVEN 支付宝旧版账单页为「账单详情 / 天猫 / 支出25元 / 交易成功 / 支付时间 2026-10-19 18:01:22 / 付款方式」
- WHEN 识别流程执行
- THEN 仍判为账单详情页并弹窗

#### Scenario: 只有成功字样但没有金额的页面不识别
- GIVEN 页面文本为「支付成功 / 完成」，没有任何可解析金额
- WHEN 识别流程执行
- THEN 不出现确认悬浮窗
- AND 在开启识别日志时记录「金额解析失败」
