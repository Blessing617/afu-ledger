# 变更：微信支付结果页识别与资产账户删除

## 动机

真实使用中出现两个挡路的问题：

1. **微信支付完成后不弹窗。** 10-21 的变更把「支付结果页」恢复成可识别来源，支付宝那边立刻见效；
   但微信的支付成功页依然完全识别不到，必须点进「账单详情」才弹窗，等于「支付过程中没有识别」。
   根因不在结果页规则本身，而在判定顺序：「账单页正向准入」（必须有账单标题或 ≥2 个强字段）
   排在结果页判定**之前**。支付宝的付款成功页自带「当前状态」「付款方式」两个强字段，能过准入这道门；
   微信支付成功页只有「支付成功 / ¥98.00 / 原价 / 优惠 / 完成」这种形态，一个强字段都凑不出来，
   于是在「正向准入」那一行就被判成「不是支付页面」直接丢弃，结果页规则根本没机会执行。

2. **建错的账户删不掉。** 资产页的账户编辑器只有「归档此账户 / 取消归档」，没有删除。
   手误建了一个不需要的账户之后，只能把它归档，从此它永远挂在资产页底部「已归档」分组里，
   还得反向「取消归档」才能恢复——一个纯粹的错误操作留下了永久的界面垃圾。

## 范围

在范围内：

- 支付结果页判定提前到「账单页正向准入」之前，结果页自身即作为准入条件
- 微信支付成功页（含「原价 / 优惠」多金额形态、无任何强字段）可识别为支付结果页并弹窗
- 无用例的页面仍不误触发：主界面、列表页、真实账单页的判定顺序与判据不变
- 资产账户编辑对话框用「删除账户」替换「归档此账户」
- 删除账户前二次确认，明确提示将连带删除的该账户交易笔数
- 移除「归档」概念：资产页「已归档」分组、归档入口、相关排序特例一并消失
- 现有被归档的账户在升级后回到普通账户列表
- 定时记账规则、自动记账默认账户在账户被删除后的降级行为
- 版本号 1.2.0，提交 GitHub 并发布正式版 APK（release 签名），手机装正式版

不在范围内：

- 不改金额解析的既有优先级规则（原价 / 优惠的排除逻辑已够用，本变更只补回归样本）
- 不为「支付结果页」新增独立开关
- 不做账户合并、交易转移、软删除/回收站
- 不改数据库其它表结构，不引入云同步或网络权限
- 不改报表形态与统计口径（删除账户后报表少掉的是该账户的历史，属于预期行为）

## 方法

识别侧只调判定顺序，不加宽任何判据：`PaymentPageDetector` 在「主界面 / 列表页排除」之后，
先判「是否支付结果页」，是则直接进入金额解析；不是才走原来的「账单页正向准入」。
结果页判据（命中成功类状态词 + 无账单标题 + 无交易单号 + 无任何账单时间字段）保持原样，
所以「首页历史通知」「钱包页」「转账待收款」这些页面不会被新顺序放进来。

账户侧复用已有 `AccountRepository.delete`（外键已设 `onDelete = CASCADE`），
补一个「按账户统计交易笔数」的查询用于确认弹窗；数据库保留 `archived` 列以免破坏备份兼容，
但升级迁移把已有归档账户统一置为未归档，界面上不再出现归档入口与分组。
