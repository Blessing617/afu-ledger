# 阿福记账 (Afu Ledger)

一个自己用的 Android 记账 App，**本地优先、无网络权限、圆润可换肤**，同时作为个人 Android 工程能力作品集开源。

## 特性

- **手动记账**：支出 / 收入、分类、账户、备注、日期选择，键盘「完成」一键保存；**居中对话框**，与「新增账户」同一套交互语言
- **自动记账**：识别微信 / 支付宝的**账单详情页**（点进去就能记），提取金额、商户与交易单号，确认卡片上标明来源（微信 / 支付宝）；微信自绘页面用**截图 + 本机离线 OCR**，支付宝走无障碍节点。交易单号做指纹，同一笔账单忽略一次就不再打扰（重启也记得）
- **资产账户**：现金 / 银行卡 / 信用卡，余额 = 初始余额 + 收入 − 支出（实时计算，不冗余存储）
- **收支报表**：月度结余与上月对照、每日支出趋势折线、分类占比环图与排行、单笔支出排行；图表全部 Canvas 手绘，切月份即时重算
- **日历视图**：首页月历标注每日收支，点某一天只看那天的账，再点一次取消；可切上下月、一键回本月
- **按日分组**：首页按天倒序展示，显示当日净额与月度汇总
- **圆润视觉**：卡片 20dp / 输入框 16dp / 胶囊按钮，统一 token 管理
- **主题换肤**：8 套主题色排成居中的 4×2 网格，选择后即时生效并持久化
- **深色模式**：跟随系统 / 浅色 / 深色三态；卡片不透明度与背景压暗在深色下自动收敛，保证文字可读
- **背景图**：从相册选择自定义背景，带缩略预览；可见度滑块 + 模糊/暗色遮罩开关，加载淡入不闪黑
- **转场动效**：标签切换带方向与纵深的 spring 过渡、二级页面纵向滑入、悬浮窗上浮弹出；曲线与时长统一由 `AfuMotion` 管理，系统关闭动画时自动退化
- **应用图标**：Q 版鲸鱼娘自适应图标
- **分类图标**：32 个可选图标（餐饮 / 咖啡 / 通勤 / 宠物 / 健身 / 工资…），每个分类带自己的柔和底色，首页、分类管理、报表用同一套视觉
- **分类管理**：内置 14 个预置分类，支持新增 / 重命名 / 换图标 / 删除（被引用的分类禁止删除）
- **完全离线**：不申请 `INTERNET` 权限，所有数据存本地 Room 数据库

## 自动记账

在「设置 → 自动记账」开启后，无障碍服务会读取微信 / 支付宝的**账单详情页**（`我 → 服务 → 钱包 → 账单`，支付宝 `我的 → 账单`），识别金额、商户与交易单号，弹出确认卡片并标明来源；点「记一笔」才入账。

**识别目标是「点进去的那一页账单」，不是付款过程中的结果页。** 这是刻意的范围收敛：账单详情页结构稳定、有交易单号可以做去重，而且用户事后补记时停在的正是这一页。

去重靠**交易单号指纹**：同一张账单忽略一次，7 天内（重启也一样）不再弹；没有单号时退化为「包名 + 金额 + 商户 + 日期」。卡片在切走应用、用户翻页、点「忽略」或 60 秒超时时自动收起 —— 一张收不掉的卡片会把后续识别全部节流掉，表现就是「自动记账彻底不工作」。

「我的」「首页」「账单列表」这类页面会被排除：真机上踩过「停在我的页却弹出 ¥25.00、商户名是广告文案」。

微信的页面是自绘的、不暴露无障碍文本节点，所以额外提供一条**截图 OCR 通道**（需在设置里单独开启）：

- 只在微信前台、且无障碍文本读不到东西时才截图
- 页面稳定判定分两档：**用户主动点击/切页后 180 ms**、其余内容变化 600 ms
- 内容变化至少隔 8 秒截一次，**用户点击/切页**至少隔 1.5 秒
- 连续几次识别不到会自动退避（间隔放大到最多 60 秒）；但**用户主动点击时仍按切页间隔放行**，不会被历史退避拦掉
- 截图进行中到来的新事件会被合并进这次识别，而不是取消它——已经付掉的截图成本不浪费
- 是否截图按**当前页面节点是否可靠**动态判断（行数与字符数双阈值），不再按包名硬编码。支付宝的账单详情页有纯原生节点，走节点通道、几十毫秒出结果；它的 H5 页面节点稀疏，才落到 OCR

> 为什么点击也算切页：微信在同一个 Activity 内翻页（聊天 → 账单列表 → 账单详情）只发内容变化事件，不发窗口状态变化事件。不把点击当换页，用户翻得比 8 秒快就会被节流拦掉、直接漏记。
>
> 为什么用户操作后不等 600 ms：点了「完成」或跳进账单页时页面已经跳完，再等 600 ms 纯属白等。

**只需要无障碍授权**，不申请 `INTERNET`、`SYSTEM_ALERT_WINDOW`、`NOTIFICATION`、`READ_MEDIA_IMAGES` 或短信权限，识别与入账全在本机完成。OCR 用 Google ML Kit 的中文文字识别（整页一次推理），模型随 APK 分发，不下载、不联网；截图只存在内存里，识别完立即丢弃，不落盘、不进日志。

边界要说清楚：

- 只处理**支出**；银行工资到账、红包到账、退款、先用后付都不在范围内
- 只适配微信与支付宝的**账单详情页与支付结果页**。**在美团、饿了么、淘宝这类 App 内付款不会触发**——它们调用微信/支付宝的 SDK 在自己的 App 里完成支付，不会跳转到微信/支付宝，账单也不在那两个应用里
- 页面同时出现两个不同金额时**直接放弃**，宁可漏记也不记错
- 账单页必须有专属证据才认（「交易单号 / 商户单号 / 收单机构」这类字段命中 ≥ 2，或标题是「账单详情」）；只出现「交易 / 订单 / 金额」这类通用词的页面不算
- OCR 会误识别，所以只做「数字上下文里的形近字符纠正」（`O→0`、`l→1`、`S→5`、`B→8`、紧邻数字的 `Y→¥`）；纠正后仍不合规（比如 `¥4Z.5O`）就整次放弃，不猜

### 识别是怎么做的

两条文本来源，对后续判定完全等价：

| 来源 | 何时使用 | 实测耗时 |
|---|---|---|
| 无障碍节点文本 | 页面节点**丰富**（行数与字符数都达标） | 几十毫秒 |
| 截图 + 离线 OCR | 节点为空或不完整（微信全部页面、支付宝的 H5 账单页） | **283–399ms**（30 行真实账单页） |

关键设计：

- **节点优先，OCR 兜底**。节点文本被判为「丰富」时先采信；即便采信了，
  只要识别未命中且 OCR 可用，仍会再试一次 OCR —— 因为有些页面（支付宝账单类 H5）
  只暴露「返回」这类导航节点，看行数是够的、看内容是空的。
- **整页一次推理**。OCR 不做「先检测文本框、再逐行识别」的两阶段。
  实测两阶段方案的成本与「所有行宽度之和」成正比（30 行要 1 次检测 + 30 次识别，
  1450–2204ms），而整页一次推理只要 283–399ms。批量推理救不了它 ——
  成本由宽度总和决定，与批次数无关（拼成大批反而更慢，窄行会被 pad 到最宽）。
- **金额只排除、不挑选**。页面上的余额（`¥217.01`）、状态栏网速（`5.24`）会先被
  上下文规则排除，剩下的若仍有多个不同金额，依然放弃识别 —— 宁可漏记也不记错。
- **主界面不触发**。看到「扫一扫 / 收付款 / 卡包」这类主界面专有入口就不识别，
  否则支付宝首页「最近消息」里的历史通知会被当成新支付。

### 后台存活：说清楚哪些能管、哪些管不了

这是无障碍类应用绕不开的一件事，如实写在这里：

**无障碍权限本身不会过期。** 它消失的唯一原因是应用被 **force-stop**
（AOSP `AccessibilityManagerService.onPackagesForceStoppedLocked`：force-stop 一个
无障碍应用会连带把它的无障碍权限从安全设置里移除）。而在这类 ROM 上，
**从最近任务把卡片划掉就等于 force-stop**。

本应用做了这些来降低影响：

- **前台服务 + 低优先级常驻通知**：把进程优先级抬出 cached 区间，降低被系统冻结的概率
- **不阻塞服务连接**：悬浮窗预热挪到 `Handler.post`。此前它是同步执行的，
  会让系统的 `wait for adding window timeout`（约 20 秒）触发并放弃绑定 ——
  表现是「开关明明开着却显示未开启」，这个 bug 已修复
- **电池优化豁免**：设置页「允许后台运行」一键申请
- **失效可被发现**：应用进程活着时用 `AccessibilityManager` 实时监听服务状态，
  一旦被撤销就发告警通知；设置页也会区分「从没设置」与「被撤销了」
- **可选：Shizuku 自动恢复**。装了 Shizuku 并授权后，`AccessibilityGuardWorker`
  每 15 分钟巡检一次，发现服务不在启用列表就静默写回
  （同一赛道的 Tally 用的就是这个办法）。没装也不影响其它功能

**做不到的部分**（不是本应用的实现问题，是平台行为）：

- 被 force-stop 之后，任何纯应用层手段都无法把权限拿回来，必须重新授权一次
- 由此推出：**别从最近任务里划掉它**。锁不锁定都不影响这一点——实测锁定后划掉仍然失效

> 实测参照：把「李跳跳」用 `adb shell am force-stop` 停掉，它同样会立刻从
> 无障碍启用列表里消失——它并没有任何保活黑科技，只是平时没被划过。

### 包体与运行时

| 项 | 大小 |
|---|---|
| release APK（含 OCR） | 约 22 MB（未含 OCR 时约 2.2 MB） |
| OCR 模型（`det.ort` + `rec.ort` + 字典） | 约 16 MB |
| ONNX Runtime（`onnxruntime-mobile`，arm64-v8a） | 约 3.7 MB |

模型用 ORT 格式、配合 `onnxruntime-mobile` 运行（full 包的 so 有 34 MB，只用 mobile 包才能把体积压到 20 MB 量级）。单次「截图 → OCR」在小米 14 Pro 上约 **640 ms**（把预览缩放交给系统 Skia 之后，从早期的约 1900 ms 降下来）。

耗时的大头是逐行串行的 rec 推理；设置页的 OCR 状态会显示最近一次的分段耗时（节点采集 / 截图 / OCR 推理 / 合计），方便定位。

### 不花钱验证

不要求真实付款。debug 构建内置了模拟页面：

```bash
adb shell am start -n com.afu.ledger/com.afu.ledger.debug.DemoPaymentActivity \
  --es scenario WECHAT_SUCCESS   # 还有 ALIPAY_BILL / AMBIGUOUS / FUTURE / REFUND / NON_PAYMENT
```

其中 `WECHAT_OCR_FULL` / `OCR_NOISE_O` / `OCR_NOISE_BAD` / `OCR_LOW_CONTRAST` / `OCR_CHAT` 用 **Canvas 自绘**，不产生无障碍节点 —— 专门用来验证截图 OCR 通道（复现微信的自绘行为）。

也可以用微信/支付宝的**历史账单详情页**（`我 → 服务 → 钱包 → 账单`）验证真实页面——发布版与 debug 构建的识别行为一致（同一笔账单只会提示一次，去重是按交易单号持久化的）。

小米 / Redmi 上如果被提示「受限制的设置」，要到应用信息右上角菜单里允许，并打开自启动、把省电策略设为「无限制」。
